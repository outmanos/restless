# 0.3.0 Files first: design (draft)

Goal: a collection is a readable file in your own folder, and the app follows it.

## Rules

- Open formats only. Use an existing open format or standard, and invent none.
- Offline. Nothing here uses the network.
- Never lose data silently. An unresolved reference is an error, not a skipped item.
- Existing files keep working and are not rewritten without a reason.

## Decided

| Topic | Decision |
|---|---|
| Native format | YAML, Insomnia's `collection.insomnia.rest/5.0` schema |
| Extension | Plain `.yaml`. A file is recognized by its `type` field |
| Bruno | `.bru` is read and written. Bruno's YAML is read |
| Templates | Nunjucks. Bruno's `{{var}}` converts on import |
| Preferences | A plain JSON file, with export and import |

## 0.3.0 scope

One YAML file per collection, as Git sync writes today, plus:

- Open any folder as a collection, and keep the app and the files in step when either changes.
- Preferences as a plain JSON file, with export and import.
- NeDB to files, with a backup first.
- `.bru` read and write, and Bruno's YAML read.

Collections stay in the monolith layout. Nothing about an existing file changes.

## Parts

1. Watcher and storage: `RepoFileWatcher` already keeps Git repositories in step with the database, one file per workspace. Generalize it to any folder.
2. Open a folder as a collection.
3. Preferences as JSON.
4. NeDB to files, with a backup first.
5. A `.bru` writer, using `@usebruno/lang`. The reader exists.

## Open

- How the database and the files relate. Suggested: the database stays a working cache and the files are authoritative for anything opened from a folder, as Git projects are today.
- History, cookies and tokens: HAR for history, a standard cookie format, tokens in the OS keychain.

## Later: split collections

Not scheduled. A big change, so it waits until the monolith storage is solid. The ideas, so they are not lost:

**Split (opt-in per collection).** The collection file lists its items, and a request lives in its own file:

```yaml
collection:
  - name: Orders
    children:
      - $ref: ./create-order.yaml
  - $ref: ./get-order.yaml
```

- `$ref` is the reference mechanism of OpenAPI and JSON Schema. A referenced file holds the item object exactly as it appears inline today.
- References are resolved relative to the file that holds them. New requests are written next to the collection by default.
- Absolute paths work only inside the folders the app is allowed to read. References never leave those folders and never fetch a URL.
- Inline and referenced items can be mixed.
- Order and folders stay in the collection file, so a reorder is a one-line diff.

### Versioning

- Monolith files keep `type: .../5.0` and `schema_version: 5.1`. A global bump would rewrite the header of every file at its next export, in every repository.
- The current reader ignores `schema_version` and silently drops `$ref` items. An older client could open a split collection with items missing and write it back without the references.
- A split collection therefore needs a `type` the older reader rejects. Insomnia already gives each document kind its own type. Open: the name, and who owns the namespace. Using Kong's next number risks a clash later.
- This reader must fail on a reference it cannot resolve.

### Loose requests

A request file that no collection references is a fragment. It can be opened on its own as a loose request, and added to a collection by writing a reference to it. This is also how the 0.4.0 "transient requests" row can be built. Files in a collection folder that nothing references are listed as unlinked.

### Work it would need

1. A loader: read a file, resolve references, then validate. The parser keeps taking a string.
2. A split writer: one collection file plus one file per request, with stable names and a round trip that reproduces each file exactly. Seven places write the format today.
3. Watcher changes: the Git watcher assumes one file per workspace. Rename, delete and move must change files, and the "canonical" round trip must hold for every request file.
4. List unlinked files, and open or attach a loose request.
5. Decided: the split type lives in a namespace restless owns. Open: its name.
